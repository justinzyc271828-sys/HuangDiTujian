## 硬规则（违反即返工）

1. **不覆盖已有人物**：写之前看 `content/sources/{id}/` 是否已存在。已有 `status: dossier-complete` 的：清单注明「复核升级」才动它（在原档案上补齐加深），否则跳过并在报告里说明；半成品一律在原有基础上补齐，不推倒重写。
2. **只写 sources 目录**：不许动 `data/emperors/`、`content/bios/`、`apps/`、`tools/` 下任何文件，也不许 `git commit`/`git push`。史料卡进产品层（界面）是另一道工序，不归你。
3. **frontmatter 不许加规范外字段**（如 batch、备注串）；字段名、取值集合严格按上表。
4. **编年排序**：E 卡按公历年升序；同年按「生 → 起兵/封立 → 即位 → 要事 → 崩 → 总评」。
5. **史实纪律**：摘要写「记载了什么」，年份锚点以本纪为准；两说并存的进 `06-争议与待考.md`，不许在摘要里选边。
6. **id 规则**：`{id}` = `data/emperors/` 里对应 YAML 的文件名（小写 kebab-case）；`person_id` 与目录名必须一致。
7. **够用即止**：摘要、要点都是给自己看的短句，不写长文，不抄大段古籍译文。

1. **先报计划**：列出本批人物 → 各自主要本纪/编年出处、预计卡数、存疑年份；等确认再写盘。
