# 史源卡 / 史料卡工作规范

> 级别定义：一张「史源卡」= 足以支撑把某位帝王从 `draft` 写到可审阅内容的**证据工作台**。  
> 现状（2026-08-09）：**全库 269 人 dossier-complete · 0 scaffold · E 卡实测 1950**；本规范为史料工作的固定准则。

---

## 1. 两套卡片，不要混

| 名称 | 英文代号 | 是什么 | 放哪 |
|------|----------|--------|------|
| **史源卡** | Source Dossier | 文献地图：读了什么、卷目、争议、置信度 | `content/sources/{id}/00-史源卡.md` |
| **史料卡** | Evidence Cards | 单条事件/论断的证据条（可多条） | `content/sources/{id}/证据/*.md` |

关系：

```
史源卡（总台）
  ├─ 指向必读书目
  ├─ 索引全部史料卡
  └─ 决定哪些证据进入 YAML 年表 / bio

史料卡（一条一事）
  └─ 年 · 事 · 地 · 原文要点 · 出处 · 是否上地图
```

产品数据层（`data/emperors`、`content/bios`）**只吃已经过史源卡筛选的结论**，不直接堆原始长文。

## 3. 史源卡「够格」标准（Ready 门禁）

一张史源卡从 `empty` → `ready-to-fill`（材料齐，可开填）需要：

- [ ] 身份字段骨架齐全（id、姓名、朝代、在位年占位）
- [ ] A 级文献至少 1 种本纪入口（书名+篇名+在哪查）
- [ ] B 级编年入口至少 1 种（通鉴卷或说明「待标卷」）
- [ ] 地图工具入口（谭图册次/CHGIS/本项目 places）
- [ ] 纪年工具入口
- [ ] 空白证据卡模板已就位
- [ ] 地点/关联/路线三张表有表头

从 `ready-to-fill` → `dossier-complete`（卡填完，可写产品）需要：

- [ ] 至少 12 条史料卡（短祚可 6 条）
- [ ] 每条有出处（书+篇/卷，允许无页码）
- [ ] 至少 5 条可上地图（有 place 候选）
- [ ] 前后任或 2+ 关联人物有着落
- [ ] `06-争议与待考` 非空或明确写「暂无重大争议」
- [ ] 史源卡顶部 `status: dossier-complete`

## 4. 史料卡字段（一条一事）

| 字段 | 必填 | 说明 |
|------|------|------|
| `eid` | 是 | E001 起编 |
| `year` | 尽量 | 公历近似，未知写 `undated` |
| `date_note` | 建议 | 年号纪年 |
| `title` | 是 | ≤12 字标题 |
| `summary` | 是 | 1–3 句史实 |
| `place_ancient` | 建议 | 古地名 |
| `place_id_candidate` | 建议 | 将来 places id |
| `on_map` | 是 | yes / no / maybe |
| `route_group` | 可选 | 巡狩/亲征/迁都… |
| `related_ids` | 可选 | 其他皇帝 id |
| `sources` | 是 | 文献列表 |
| `quote_note` | 可选 | 自用大意，勿大段版权译文 |
| `confidence` | 是 | high / medium / low |
| `enter_product` | 是 | 是否进入 YAML 年表 |

## 5. 状态机

```
empty → ready-to-fill → in-progress → dossier-complete → product-synced
                              ↑              │
                              └──── 修订 ←───┘
```

| status | 含义 |
|--------|------|
| `empty` | 只有模板 |
| `ready-to-fill` | 书目与工具齐，等人开填 |
| `in-progress` | 正在做证据卡 |
| `dossier-complete` | 证据够写 bio/YAML |
| `product-synced` | 已写入 data/ + content/bios |

---

## 6. 与产品数据的同步规则

1. 先改史源/史料卡，再改 `data/emperors/{id}.yaml`  
2. bio 中的 `[[链接]]` 必须在关联表或史料卡里出现过  
3. `published` 状态禁止无 A 级出处的事件  
4. 画像字段本阶段全部 `placeholder`，不阻塞史源卡
