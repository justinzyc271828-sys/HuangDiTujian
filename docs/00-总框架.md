# 《皇帝图鉴》项目总框架

> 版本：v0.1 · 状态：立项规划 · 日期：2026-08-05  
> 仓库：`HuangDiTujian` · 目标：把中国历史上全部正式帝王 + 准帝王做成可跳转、可地图化的交互式人物图鉴

---

## 1. 一句话定位

**《皇帝图鉴》** 是一本可交互的「中国帝王收集图鉴」：以史书描述驱动 AI 生成相貌，以结构化史实驱动事迹年表与关联网，以古地图侧栏呈现每位帝王一生的空间轨迹。

它不是百科词条堆砌，也不是纯美术立绘集，而是：

| 维度 | 说明 |
|------|------|
| 图鉴感 | 可浏览、可筛选、可「收集进度」式总览（像图鉴册） |
| 史书感 | 每页有主要事迹、年表、关联表，可追溯到史料出处 |
| 游戏感 UI | 页面精美、侧栏地图可展开，人物之间可跳转 |
| 可扩展 | 先正式帝王，后期补准帝王；数据与表现分离 |

## 2. 最终交付产物（建议主路径）

### 2.1 主交付：交互式 Web 图鉴应用

**推荐形态：静态可部署的 Web App（SPA / SSG）**

| 产物 | 形态 | 用户价值 |
|------|------|----------|
| **图鉴主站** | 浏览器打开的 Web 应用 | 总览、筛选、搜索、人物页、跳转、地图 |
| **人物页** | 每位帝王一页（深链可分享） | 画像 + 事迹 + 年表 + 关联 + 路线图 |
| **关联跳转** | 正文 `[[链接]]` / 高亮标注 | 点到其他皇帝即跳转对应页 |
| **侧栏古地图** | 可展开/收起 | 一生主要地点与迁徙/征伐路线 |
| **数据源仓库** | 本 Git 仓库 | 内容可审、可改、可版本管理 |

**为什么先做 Web，而不是 App / 纸书 / Unity：**

1. 交叉链接与地图交互天然适合浏览器  
2. 可先本地打开 / GitHub Pages / 任意静态托管  
3. 后续可再导出「印刷图鉴 PDF」「EPUB」「桌面壳」  
4. AI 素材与 Markdown/JSON 内容管线最容易协作  

### 2.2 次级交付（可选，后期）

| 产物 | 时机 | 说明 |
|------|------|------|
| 印刷向 PDF / 宣纸风电子画册 | 内容稳定后 | 按朝代分册导出 |
| 离线桌面版（Tauri / Electron） | 需要离线体验时 | 复用同一套 Web 前端 |
| 移动端适配 / PWA | 主站可用后 | 手机翻图鉴 |
| 开放数据集 | 愿意开源时 | `data/` 可单独发布 |

### 2.3 明确「不是」什么（边界）

- 不是完整中国通史教材（聚焦「人」与其轨迹）  
- 不是严格学术数据库（可引出处，但不替代二十四史索引）  
- 第一期不做：3D 场景、实时对战、UGC 社区、登录体系

## 3. 收录范围

### 3.1 三层收录（分期落地）

| 层级 | 代号 | 定义（工作标准） | 优先级 |
|------|------|------------------|--------|
| **正式帝王** | `emperor` | 中原或主要统一/割据王朝之「帝」「王」且被传统正史帝纪收录，或史学上通常列入帝王谱系者 | P0 先做 |
| **准帝王** | `quasi` | 称帝未久、割据称王、短命政权、伪朝、禅让前后名义帝、部分「监国/称制」等需单独判定者 | P1 后期补 |
| **追尊 / 名义** | `honorary` | 死后追尊、未实际称制者；默认折叠，可开关显示 | P2 可选 |

> 「准帝王」名单争议大，必须每条有**收录理由**字段，避免无限膨胀。

### 3.2 分期建议（可执行）

1. **MVP**：秦 → 清「主流正统线」抽样 8–12 人，跑通整条管线  
2. **V1**：秦 → 清主流正式帝王（按朝代分批录入）  
3. **V1.5**：南北朝 / 五代十国 / 十六国等正式列入帝纪者  
4. **V2**：准帝王扩展包（单独开关，UI 上用「宣纸略正式」视觉区分）

## 4. 单页「人物图鉴」信息架构

每位帝王一页，建议固定模块（可折叠）：

```
┌─────────────────────────────────────────────────────────────┐
│  [返回图鉴]  秦 · 始皇帝  嬴政                    [收藏★]   │
├──────────────────────────────┬──────────────────────────────┤
│                              │  ▸ 侧栏：古地图（可展开）      │
│   AI 画像 / 立绘区            │    · 一生主要地点            │
│   （可切换：正史风 / 写实风） │    · 迁都 / 巡狩 / 征伐路线  │
│                              │    · 点击地点 → 事件浮层      │
│   庙号谥号 · 年号 · 在位     │                              │
├──────────────────────────────┴──────────────────────────────┤
│  ① 速览卡：一句话定位、在位时间、都城、重大标签               │
│  ② 主要事迹（精修短文，含 [[其他皇帝]] 跳转）                 │
│  ③ 年表大事表（时间轴 / 表格双视图）                         │
│  ④ 关联表：亲属 · 权臣 · 对手 · 相关帝王 · 相关地点          │
│  ⑤ 史料与生成说明：画像依据、文字出处、置信度                 │
└─────────────────────────────────────────────────────────────┘
```

### 4.1 各模块最低字段

**A. 身份头**

- `id`（稳定英文/拼音 slug，如 `qin-shi-huang`）  
- 姓名、庙号、谥号、尊号、常用称呼  
- 王朝 / 政权、序列（第几位）  
- 在位起止（公历 + 可选年号纪年）  
- 出生/去世（若可知）  
- 收录层级：`emperor | quasi | honorary`  

**B. 画像**

- 主图路径、多风格变体  
- 生成 prompt、史书外貌依据摘录  
- 风格版本号（保证全库视觉统一）  

**C. 主要事迹**

- Markdown 正文（支持 `[[slug|显示名]]` 交叉引用）  
- 3–8 条「高光标签」（如：统一六国、焚书坑儒…）  

**D. 年表大事表**

- 有序列表：`year` / `date_note` / `title` / `summary` / `place_id?` / `related_person_ids[]` / `sources[]`  

**E. 关联表**

- 类型：`kinship | rival | minister | successor | predecessor | related_emperor | other`  
- 目标 `id` + 关系说明  

**F. 地图轨迹**

- 有序点/线段：`place_id`、`year?`、`event`、`path_group`（迁都/亲征/流放…）  
- 地点库统一维护古今对照坐标

## 5. 系统总架构

```
                    ┌──────────────────────┐
                    │   内容生产管线         │
                    │ 史源 → 结构化 → 审校  │
                    │ 画像 prompt → AI 出图  │
                    └──────────┬───────────┘
                               │ 写入
                               ▼
┌────────────────────────────────────────────────────────────┐
│                     本仓库数据层                            │
│  data/emperors/*.yaml   人物主数据                         │
│  data/places/*.yaml     地点与古今坐标                     │
│  data/dynasties.yaml    王朝元数据                         │
│  content/bios/*.md      长文事迹（可选）                    │
│  assets/portraits/      画像                               │
│  assets/maps/           底图与装饰                         │
└────────────────────────────┬───────────────────────────────┘
                             │ 构建时校验 + 索引
                             ▼
┌────────────────────────────────────────────────────────────┐
│                     应用层 Web App                          │
│  图鉴总览 · 搜索筛选 · 人物页 · 链接解析 · 地图侧栏         │
└────────────────────────────────────────────────────────────┘
```

### 5.1 技术建议（可调整，先定原则）

| 层 | 建议 | 理由 |
|----|------|------|
| 前端 | Vite + React + TypeScript | 交互与组件生态成熟 |
| 样式 | Tailwind + 自研「宣纸/金石」主题 token | 易做图鉴美学 |
| 路由 | React Router（或 SSG 用 Astro/Next） | 每人一页深链 |
| 地图 | SVG 古地图底图 + 自绘路线；后期可换 MapLibre | 古地名不必绑现代瓦片 |
| 数据 | YAML/JSON + 构建时生成索引 | 非程序员也可改内容 |
| 校验 | Zod / JSON Schema + CI | 防止坏链接、缺图 |
| 部署 | 静态托管（GitHub Pages / Cloudflare） | 零后端 MVP |

**原则：内容与代码分离。** 以后换前端，数据资产不废。

### 6.2 视觉类

| 素材 | 说明 | 备注 |
|------|------|------|
| **画像风格板（Style Bible）** | 统一构图、光影、服装纹样、背景留白 | 先定 3 张锚点图再批量 |

| **UI 装饰** | 边框、印章、宣纸底、标题字体 | 可矢量自制 |
| **图标** | 朝代、标签、地图控件 | 统一线性/金石风 |
| **参考 UI 截帧** | B 站 BV1SEK96HEWK 等交互参考 | 需本地浏览录屏/截图进 `docs/references/` |

### 6.3 地图类

| 素材 | 说明 |
|------|------|
| **中国古代总览底图**（SVG） | 海岸线+主要山脉简化；不要求精确现代投影 |
| **地点库** | 古名、今地对照、近似经纬度、所属政权阶段 |
| **路线样式规范** | 颜色：亲征/巡狩/迁都/流放；虚实线规则 |

### 6.4 工程类

| 素材 | 说明 |
|------|------|
| 人物 YAML 模板 | 见 `data/templates/emperor.template.yaml` |
| 地点 YAML 模板 | 见 `data/templates/place.template.yaml` |
| 交叉引用语法规范 | `[[qin-shi-huang\|秦始皇]]` |
| Prompt 模板库 | `tools/prompts/` |
| 构建与校验脚本 | 链接检查、缺图检查、id 唯一性 |

### 6.5 法务与伦理（轻量但必要）

- AI 画像标注「据史书描写之艺术想象，非考古复原」  
- 史料引用用公开古籍/通行本，避免大段现代版权译文照搬  
- 肖像风格避免直接复刻在世画师可识别风格

## 7. 交互与体验规格（对齐你的设想）

### 7.1 图鉴总览

- 朝代时间轴 / 网格卡片双模式  
- 筛选：朝代、层级（正式/准）、标签、在位时长  
- 搜索：姓名、庙谥、年号、别称  
- 可选「收集进度」：本地标记已读/收藏（localStorage 即可）  

### 7.2 交叉跳转

- 正文与表格中的其他皇帝：  
  - 视觉：下划线 / 印章色高亮 / 小皇冠图标  
  - 行为：点击进入目标人物页；支持浏览器前进后退  
- 坏链接在构建期报错，不在运行时静默失败  

### 7.3 侧栏地图

- 默认窄条预览，一键展开为半屏/全屏  
- 展示：关键地点标记 + 有序路线  
- 与年表联动：点年表 → 地图高亮对应点；点地图 → 滚动到事件  
- 视觉：古卷/木框边，避免谷歌地图现代感  

### 7.4 准帝王视觉

- 页面纸色略旧、边框略简、角标「准」  
- 与正式帝王同一信息结构，降低后期补录成本

## 8. 内容生产工作流（推荐流水线）

```
选题入表 → 填 YAML 骨架 → 写事迹与年表 → 标关联与地点
    → 写外貌依据与 prompt → AI 出图 → 人工选图调色
    → 本地预览校验 → 合入 main → 静态站点更新
```

**最小可用一条龙（单人也能跑）：**

1. 复制模板创建 `data/emperors/qin-shi-huang.yaml`  
2. 写 `content/bios/qin-shi-huang.md`（或把短文直接放 YAML）  
3. 地点复用 `data/places/`  
4. 生成画像放入 `assets/portraits/qin-shi-huang/`  
5. `npm run dev` 预览人物页

## 11. 风险与对策

| 风险 | 对策 |
|------|------|
| 收录范围无穷扩大 | 分层 + 收录理由字段 + 分期 |
| AI 画像千人一面 | Style Bible + 外貌依据字段强制填写 |
| 史实错误被传播 | 出处字段 + 显著「修订中」标记 + 优先用通行共识 |
| 古地名坐标不准 | 地点库标注 `precision: approximate` |
| 工程过度设计 | M1 只做垂直切片，不做账号/社区 |

## 13. 成功标准（怎样算「立起来了」）

**立项成功（M0）：** 有清晰产物定义、数据模板、空壳可运行结构。  

**演示成功（M1）：** 打开网站 → 从图鉴点进一位皇帝 → 读事迹 → 点 `[[另一位]]` 跳转 → 展开地图看路线。  

**产品成功（M3+）：** 正式帝王主线可连续翻阅，视觉统一，坏链为零，可对外分享。
