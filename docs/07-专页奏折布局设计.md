# 皇帝专页 · 奏折布局设计（定稿方向）

> 状态：**产品交互定稿** · 前端实现 **槽位预留**（不在本阶段由现有 Lab 样式充当正式 UI）  
> 日期：2026-08-06  
> 原则：**史实准确 + 游戏化/有趣展示**；外壳可玩，内核可查。

---

## 1. 产品一句话

点进某位皇帝 = **打开一份奏折**：  
左右展开；**左目录 · 中主文（含六维） · 右一生地图**。

现有「替身档 Lab」仅作历史实验，**不作为正式专页**。正式前端按本文重做。

---

## 2. 交互流程

```
图鉴总览（卡片墙，可另定）
    ↓ 点击皇帝
过场：奏折合页 → 左右翻开（动效可选）
    ↓
奏折展开态（本页主态）
    ├─ 左：索引目录（锚点跳转）
    ├─ 中：主界面（事迹 / 年表 / 六维 / 关联…）
    └─ 右：一生地图（路线 / 地点）
```

### 2.1 合页态（可选首屏）

- 中央可见奏折封面：庙号/谥号/姓名、朝代、短句 summary  
- 操作：「展开御览」或点击折面  
- 目的：仪式感；可跳过（设置「直接展开」）

### 2.2 展开态（默认推荐）

三栏固定骨架（桌面）；移动端改为：顶栏目录抽屉 + 中主文 + 底/次屏地图。

---

## 3. 三栏信息架构

### 左栏 · 索引目录（约 18–22% 宽）

| 项 | 说明 |
|----|------|
| 身份摘要 | 显示名、姓名、在位年 |
| 目录锚点 | 速览 / 事迹 / 六维品藻 / 年表 / 关联 / 出处 / （可选）收藏 |
| 状态 | 已读、收藏、tier（正式/准） |
| stub | 灰卡仅显示「待撰写」+ 基本身份，目录项灰色不可跳 |

点击目录 → 中间栏 smooth scroll 到对应 section。

### 中栏 · 主界面（约 45–52% 宽）

滚动主内容，建议顺序：

1. **卷首**  
   - 标题区（朝代 · 庙谥 · 姓名）  
   - 一句话 summary  
   - 标签 tags  
   - 画像占位（可后补）  

2. **六维品藻**（固定模块，游戏化）  
   - 雷达图 + 六轴等级（E–A+）  
   - 能力/破绽短文（娱乐包装）  
   - 脚注：「品藻戏作；史实见年表与出处」  

3. **主要事迹**  
   - 可含 `[[其他皇帝]]` 跳转  

4. **年表大事**  
   - 与史料卡/YAML timeline 同步  
   - 可点事件 → 右侧地图高亮  

5. **关联表**  

6. **出处**  

### 右栏 · 一生地图（约 28–32% 宽）

| 项 | 说明 |
|----|------|
| 示意底图 | 非严肃 GIS 亦可，但坐标尽量 honest |
| 路线弧线 | 按 routes[] |
| 事件列表 | 与年表联动 |
| stub | 显示「路线未录入」 |

侧栏可 sticky；窄屏折叠为「附图」按钮。

## 4. 六维定义（已定，可微调文案）

| key | 品藻 | 游戏感别名 | 含义 |
|-----|------|------------|------|
| military | 武功 | 破坏力 | 征伐、拓边 |
| strategy | 机略 | 速度 | 决断与政局反应 |
| range | 疆域 | 射程 | 势力与空间控制 |
| endurance | 国祚 | 持续力 | 在位稳定与续命 |
| precision | 精密 | 精密度 | 制度与集权精度 |
| legacy | 余波 | 成长性 | 后世影响 |

数据：`data/catalog/stand_stats.json`（及将来写入每人 YAML 的 `radar` 字段）。

---

## 5. 视觉气质（给前端的约束，不指定烂实现）

**要：**

- 奏折/经折的「打开」隐喻（折痕、封套、展开）  
- 可游戏化：六维、等级、短句「必杀/破绽」式包装  
- 信息分区清晰，目录可点  

**不要：**

- 做成现代 SaaS 白卡片堆叠当正式专页  
- 做成假严肃论文排版却没目录/地图  
- 为酷炫牺牲史实模块（年表/出处必须在）  

色板、字体、动效：**交给专职前端/设计**；本文只锁结构。

## 6. 前端实现槽位（预留）

### 6.1 建议路由

| 路由 | 职责 |
|------|------|
| `/` | 图鉴总览 |
| `/emperor/:id` | **奏折专页（正式）** |
| `/lab` | 实验页（可删可藏，非正式） |
| `/rank` | 品第榜（后续） |

### 6.2 建议组件边界（谁写前端接这些）

```
EmperorMemorialPage          # 奏折壳：合页/展开
  MemorialCover              # 合页
  MemorialSpread             # 三栏展开
    MemorialToc              # 左目录
    MemorialMain             # 中主文
      SectionHero
      SectionRadar           # 六维
      SectionBio
      SectionTimeline
      SectionRelations
      SectionSources
    MemorialMap              # 右地图
```

### 6.3 数据契约（已有 / 将有）

| 数据 | 来源 |
|------|------|
| 身份、timeline、routes、relations、bio | `data/emperors/*.yaml` → `site.json` |
| 地点 | `data/places` → `site.json` |
| 六维 | `data/catalog/stand_stats.json`（扩展到全员后可 merge 进 site） |
| 全库索引 | `data/catalog/emperors_master.json` |
| stub | `page_status === "stub"` 时简化中栏 |

### 6.4 明确不做（本仓库当前 AI 实现）

- 不再迭代 `/lab` 多皮肤当正式方案  
- 不把现有卡片专页当最终视觉  
- 视觉稿 / 高保真 UI 由人工前端接 `07` 本文落地

## 7. 与游戏化总览的关系

| 层级 | 气质 |
|------|------|
| 总览图鉴墙 | 可继续游戏化（收集、灰卡未启封、筛选） |
